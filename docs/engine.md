# グライド入力エンジン

`GlideDecoder` は、ストロークから得た幾何モデル A と、文脈・読みの途中までから得た文字言語モデル B を、文字を追加する段階で結合します。この探索中に、同梱 Sumire 辞書の読み・単語コスト・品詞接続コストも評価します。その後、候補の読みを辞書ベースの `KanaKanjiConverter` に渡します。文字言語モデルに漢字変換をさせる構成ではありません。

## A: ストロークの確率格子

`StrokeModel.lattice(trace)` は Android に依存しない処理です。座標をキーの幅・高さで正規化し、疎なタッチ座標の間を補間して、通過したキーの区間を求めます。各区間は「かなを 1 文字出力」または「通過して出力しない」の分布 `StrokeEvent` になります。

- 最初と最後の区間は文字を出力します。
- 途中の直線的な通過は省略しやすく、曲がり角やキー中心での滞留は文字を出力しやすくします。
- 文字の分布はキー中心からの距離で決まり、周辺キーも候補になります。
- 同じキーから離れて戻る操作や、キー内で中心から離れて戻る小さなループは連続する同じ文字を表せます。静止した長押しだけでは文字を増やしません。
- 濁音・半濁音・小書き文字は元のキーから固定の事前確率で出します。例えば `か` は `か/が/ゕ`、`や` は `や/ゃ` を表せます。

各イベントについて、文字の確率とスキップの確率の和は 1 です。格子の各経路の確率はイベント選択の確率の積です。同じ読みになる経路の確率を合算すると `A(reading | stroke)` になります。意味、単語辞書、直前の文章はこのモデルに入りません。

現在の距離・曲率・滞留・異体かなの重みはヒューリスティックです。実際の指の軌跡から学習・校正した認識率を主張するものではありません。直線の途中にある文字を意図的に入力したか、単に通過したかは幾何情報だけでは一意に定まりません。

## B: かな 1 文字ずつの予測

`KanaLanguageModel.nextLogProbabilities(context, prefixes)` は、同じ文脈に対する複数の読みの途中までをまとめて受け取り、各 prefix に対応する「次のかな」の自然対数確率を返します。デコーダーは同じ呼び出し内で prefix ごとに結果をキャッシュします。異なる文脈・異なる入力をまたいだキャッシュは持ちません。

`hukuda222/hiragana-gpt2-xsmall` の ONNX 実装はこのインターフェースに接続されます。モデルファイルの生成・配置方法とライセンスはプロジェクトの README とモデル準備ツールを参照してください。確率が存在しない文字は B の下で出現不可能として扱います。モデルが利用できない場合の扱いは上位の候補エンジンが担当し、デコーダー自身は架空のモデル出力を作りません。

## 結合とビーム探索

各イベントで、現在の候補について B をバッチ評価し、スキップと文字追加を展開します。同じ読みを持つ候補は A の対数確率を log-sum-exp で合算してから、次のスコアで枝刈りします。

```text
score = strokeWeight * log A
      + languageWeight * log B
      + characterInsertionBonus * 読みの文字数
      - dictionaryWeight * dictionaryCost
```

既定値は `strokeWeight = 1.0`、`languageWeight = 0.35`、`characterInsertionBonus = 0.0`、`dictionaryWeight = 1.0` です。B は次の文字の条件付き確率の積で、EOS の確率は加えていません。この積には短い読みを好む傾向があります。`languageWeight` と文字追加ボーナスは、実際のストロークと正解読みの評価用データを用いて調整してください。文字追加ボーナスを設定した場合、その項も順位付けに含まれます。

`ReadingLexicon.newSession()` が探索1回の辞書状態を作り、読みを1文字延ばすたびに LOUDS の読みトライと語分割の Viterbi 状態を更新します。単語の途中として存在するprefixも候補に残ります。最終イベントでは、未完prefixの仮スコアではなく完了した語分割・EOSのコストを使ってから枝刈りします。同じprefixの累積辞書コストをその都度置き換えるため、辞書コストをイベントごとに重ねて加算することはありません。

`dictionaryCost` は生の単語・品詞接続コストに語境界ペナルティを加えてスケールした評価値であり、対数確率ではありません。語境界のコストで短語の過剰な連結を抑え、辞書にない文字にも高コストの有限経路を用意しています。既定では16本のビーム中2本をA+B側の順位で残し、返却候補にも1本の枠を確保します（幅・返却数が1の場合は辞書混合の最上位を優先）。これにより人名・新語を完全に排除せず、表示順は混合スコア順に保ちます。

辞書を使わない比較は `dictionaryWeight = 0.0`。辞書のセッション作成・評価を省略し、以前のA+B探索になります。辞書を渡さない `GlideDecoder` もA+Bのみです。具体的なコストと探索上限は [変換エンジン](conversion.md) を参照してください。Aの確率格子には辞書情報を入れていません。

`ReadingCandidate` は読み、A の対数確率、B の対数確率、辞書コスト、最良の語分割の未知文字数、結合スコア、`posterior` を返します。A は枝刈り後に残った経路についての近似です。`posterior` は**返却候補だけ**に対するスコアの softmax であり、すべての読みについての厳密な事後確率や、校正済みの認識信頼度ではありません。返却件数を変えると `posterior` の値も変わります。

`languageWeight = 0.0` では言語モデルを呼びません。この場合 `languageLogProbability` は未評価を表す `0.0` です。Aのみを確認するには `dictionaryWeight = 0.0` も指定します。

## 計算量と中断

既定では入力点 8,192 個、補間点 1,024 個、格子 48 イベント、ビーム幅 16、読み長 32 文字、返却 8 候補までです。1 イベントにつき最大 1 回のモデル呼び出しを行い、既に評価した prefix は再計算しません。イベント数を超える落書きのような入力や、不正な座標・逆転した時刻は候補なしとして扱います。

デコーダーはスレッドの割り込みを保持したまま `InterruptedException` を送出します。既定 5 秒の時間制限を処理の区切りで確認し、超過時は `GlideDecodeTimeoutException` を送出します。実行中のネイティブ推論の中断は `KanaLanguageModel.cancelPendingInference()` とモデル実装が担当します。時間制限は割り込み不能な外部実装の処理時間までは保証できません。

## 検証

`GlideDecoderTest` は直線の途中のキーの省略、角と滞留の認識、戻り・小ループと長押しの区別、濁音と小書き文字の文脈選択、A の文脈非依存性、経路確率の合算、確率の正規化、prefix のバッチ化とキャッシュ、長さ補正、無効入力、中断、プロバイダーの不正応答を検証します。

`DictionaryBeamTest` は辞書を使わないと途中で落ちる読みの救済、最終イベントでの完了コストの評価、累積コストの二重加算防止、未知語経路の保持、辞書無効時の挙動を検証します。辞書で未知文字を含むと判断した読みは、UI候補では漢字断片へ変換せずそのままのかなを残します。ただし、短い辞書語へ分解できる不自然な列は未知扱いにならないため、辞書だけで非単語をすべて除去できるわけではありません。

Pixel 8の実モデル比較では、キー内のずれと丸い曲がりを含み、各キーに滞留しない同一の合成軌跡について次の結果を確認しました。LLM重み・ビーム幅・Aの設定は共通で、変更は辞書混合の有無だけです。

| 正解の読み | 辞書なしの正解順位 | 辞書ありの正解順位 |
| --- | --- | --- |
| こんにちは | 4 | 2 |
| ありがとう | 1 | 1 |
| にほんご | 2 | 1 |
| とうきょう | 上位8件外 | 上位8件外 |

この4件の候補生成は、モデル読込後で辞書なし138〜335ms、あり276〜559msでした。1回の合成軌跡比較であり、実利用の認識率・応答時間の保証ではありません。軌跡による文字抜け、候補外の正解、辞書に存在する別単語への誤認識は引き続き改善対象です。
